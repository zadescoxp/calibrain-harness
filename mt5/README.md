# Calibrain MT5: مستشار الوكلاء الستة

إضافة MT5 مستقلة عن منصة Bybit/Python الحالية. التنفيذ النشط هو Expert Advisor معياري مكتوب بـ MQL5؛ يركّب على رمز الرسم الحالي ويُختبر في MT5 Strategy Tester.

> **مهم:** يبدأ المستشار بالمراقبة فقط (`InpEnableTrading=false`). إرسال الأوامر لا يعمل إلا بعد تفعيله يدويًا في Strategy Tester أو على حساب تجريبي؛ لا يمكنه التداول على حساب حقيقي. لا تضمن أي استراتيجية أرباحًا. اختبر على بيانات وسيطك وحساب تجريبي، فنتائج الاختبار الخلفي لا تضمن الأداء المستقبلي.

## النسخ والملفات

- **التنفيذ المعتمد:** `Experts/CalibrainAgents/CalibrainAgents.mq5` مع الوحدات في `Include/Calibrain`. هذا هو الملف الذي يُثبّت ويُجمّع ويُشغّل.
- **مرجع تاريخي فقط:** `MT5_Trading_Engine.mq5` أحادي الملف محفوظ كما هو للمقارنة، وليس التنفيذ الحالي ولا يدخل في خطوات التثبيت.

```text
mt5/
  Experts/CalibrainAgents/CalibrainAgents.mq5
  Include/Calibrain/Types.mqh
  Include/Calibrain/Logger.mqh
  Include/Calibrain/Agents/{Atlas,Vega,Orion,Titan,Luna,Nova}.mqh
  tools/Install-MT5.ps1
  MT5_Trading_Engine.mq5            # مرجع تاريخي فقط
```

## الوكلاء ومسار القرار

| الوكيل | المنطق |
|---|---|
| **Atlas** | يقيس اختلال دفتر السوق عند توافر Market Depth، وإلا يرصد قفزة tick volume مع اتجاه الشمعة. هذه بيانات وسيط وليست تدفقًا فعليًا لهويات المؤسسات أو «الحيتان». |
| **Vega** | يقيس توازن الاتجاه عبر EMA 20/50، ميل المتوسط السريع، RSI وADX؛ يرفض الاتجاه الضعيف أو الممتد. |
| **Orion** | لا ينشئ فكرة إلا بعد إغلاق الشمعة: اتجاه المتوسطات، اختراق قمة/قاع الشمعة السابقة، نطاق RSI وموافقة Vega وحد الثقة. يضع وقفًا 1.5 ATR وهدفًا افتراضيًا 1.5R. |
| **Titan** | يمنع الدخول عند اتساع السبريد أو انخفاض ATR، وخلال نافذة تدوير منتصف الليل؛ ويمكنه حصر ساعات الجلسة حسب توقيت خادم الوسيط. |
| **Luna** | يدير الخروج على كل tick: يحرك الوقف إلى التعادل بعد 1R ويتتبع السعر بوقف ATR بعد 1.5R؛ لا يوسّع الوقف. |
| **Nova** | يحسب الحجم من نسبة المخاطرة وقيمة النقطة، ويرفض الحد الأدنى للوسيط إذا تجاوز الميزانية، ويتابع خسارة اليوم والمخاطرة المفتوحة وعدد المراكز والهامش. |

تُحلل الإشارة مرة لكل شمعة مكتملة. لا تستخدم الاستراتيجية خدمات خارجية أو نموذجًا لغويًا لاتخاذ قرارات التداول.

## التثبيت والتجميع

1. ثبّت MT5 وسجّل الدخول إلى حساب تجريبي لدى وسيطك. اعثر على مجلد بيانات الطرفية عبر **File → Open Data Folder**.
2. من PowerShell في جذر المستودع شغّل:

   ```powershell
   .\mt5\tools\Install-MT5.ps1 -TerminalDataPath "$env:APPDATA\MetaQuotes\Terminal\<instance-id>"
   ```

   يمكن حذف `-TerminalDataPath` إذا كانت هناك نسخة طرفية واحدة فقط قابلة للاكتشاف.
3. افتح MetaEditor، وافتح `MQL5\Experts\CalibrainAgents\CalibrainAgents.mq5` واضغط **Compile**. تُنسخ ملفات التضمين إلى `MQL5\Include\Calibrain`.
4. أرفق `CalibrainAgents` برسم كل رمز تريد مراقبته. ابدأ بمراجعة السجل في وضع المراقبة. اختبر التنفيذ على حساب تجريبي فقط.

السجل يُكتب في **Experts** وفي `MQL5\Files\CalibrainAgents\calibrain.csv`. يدمج حد المراكز والمخاطر المراكز ذات Magic Number نفسه عبر الرموز عند تشغيل نسخة لكل رسم. تجنب تشغيل نسخ متعددة على الرسم نفسه.

## ضوابط الإعدادات الافتراضية

| الإعداد | القيمة |
|---|---:|
| إرسال الأوامر | `false` |
| الحساب المسموح بالتداول عليه | تجريبي فقط |
| المخاطرة لكل صفقة | `0.25%` من equity |
| أقصى مخاطرة مفتوحة | `1.0%` من equity |
| حد خسارة اليوم | `2.0%` من baseline اليومي |
| الحد الأقصى للمراكز | `3` لكل Magic Number |
| استخدام الهامش الحر للصفقة | `20%` |
| إطار القرار | M15 |
| عائد/مخاطرة مستهدف | `1.5R` |
| حد الجلسة | معطل؛ الساعات عند تفعيله بتوقيت خادم الوسيط |

حد السبريد وATR معرف بالنقاط الخاصة برمز الوسيط. راجع حجم العقد والحد الأدنى للوت وقيمة النقطة والرافعة وساعات التداول وتكاليف التنفيذ. يُخزّن baseline اليومي في Global Variables الخاصة بالطرفية؛ لا تحذفها خلال اليوم إذا أردت استمرار حد الخسارة بعد إعادة التشغيل.

## المحاكاة في Strategy Tester

1. افتح **View → Strategy Tester** واختر `CalibrainAgents`، الرمز وإطار M15.
2. استخدم **Every tick based on real ticks** عند توافر البيانات، وفترة تشمل ظروف سوق متنوعة، ورصيدًا ورافعة قريبين من الحساب التجريبي.
3. ابدأ بـ `InpEnableTrading=false` لمراجعة الإشارات؛ ثم اختبر التنفيذ على حساب تجريبي. افصل فترة لاحقة للتحقق بدل تحسين الإعدادات على فترة واحدة.
4. راجع التراجع، التكاليف، رفض الأوامر وحساسية النتائج للسبريد والانزلاق. قد تختلف بيانات DOM والتنفيذ بين الوسطاء.

اختبارات Python الخفيفة في جذر المشروع تتحقق من بنية الوكلاء وتوصيل الحواجز الآمنة. يلزم MetaEditor للتحقق من التجميع، وStrategy Tester لمحاكاة تنفيذ الوسيط.

لا توجد صور استراتيجية مرفقة في سياق التنفيذ المتاح؛ لذلك يعتمد هذا الإصدار على قواعد فنية قابلة للقياس، لا على تحليل صورة غير متاحة.
